Marketplace · assistant access

Let an assistant follow your rental status.

Approve a connection in your local Common Foundry Renter app. The assistant can then read the rental status that app shares for up to one hour.

Connect

  1. Use a renter release whose notes include Assistant access. Find it in the renter releases, then open your mainnet renter profile.
  2. In a compatible client's remote MCP settings, add https://commonfoundry.ai/rent/mcp and choose OAuth authentication.
  3. The Common Foundry sign-in page shows the requesting app, its callback host, and an eight-character code.
  4. In the renter app, open Connection → Assistant access. Enter the code, choose Review request, verify the app and callback host, then choose Allow status access for one hour.
  5. Return to the sign-in page and continue. Ask the connected assistant to report your current rental status and its observation time.

What is shared?

The get_my_rentals tool returns rental phases, authorized and elapsed seconds, launch and settlement state, and whether the renter's node observation is current. Rental IDs identify the records within your approved profile.

The permission is rentals:read. It provides no rental creation, stopping, renewal, payment, refund, withdrawal, wallet, or SSH capability. Wallet balances, wallet keys, and SSH connection details are excluded from shared status.

Freshness and revocation

Keep the local renter app available while sharing. Observations older than five minutes are unavailable. An offline app or failed status read produces an error rather than an invented empty rental list. These are renter-reported observations, not an independent verification of the host or chain.

In Connection → Assistant access, revoke a connection or revoke all assistant access. Access also ends one hour after approval. If server revocation cannot be confirmed, the app pauses sharing and retains the pending revocation for retry.

For integrators

Read the marketplace authentication procedure, authorization-server metadata, and protected-resource metadata. OAuth authorization codes use PKCE S256. Client ID Metadata Documents are supported, with dynamic client registration for compatible older clients.

The separate public MCP service serves network data and maintained guides without signing in.

First release: read-only rental status. Client compatibility and renter release requirements apply.
