# Common Foundry v0.1.0-devnet.14

Devnet-14 is a private testing candidate that combines the persistent peer and
multi-vendor miner work from the unpublished Devnet-12/13 candidates with the
latest ForgeMatrix production-proof research. It remains on the existing
Devnet-0 chain. The production proof profile is still disabled.

## Changes

### Wallet networking and diagnostics

- Added a persistent peer manager to the desktop wallet. Testers can add,
  remove, and reset outbound peers from the Network screen.
- Numeric peer addresses default to TCP port `18444`; validated settings are
  applied immediately and restored after restart.
- Retained structured node logging and clearer startup diagnostics while
  keeping wallet RPC local to the computer.

### Standalone mining

- Retained CUDA targets for Volta and NVIDIA RTX 20-, 30-, 40-, and 50-series
  GPUs, plus the `compute_70` PTX fallback.
- Retained deeper CUDA scheduling and explicit multi-GPU throughput controls.
- Included the runtime-loaded OpenCL backend for Intel Arc, with device
  enumeration and explicit backend selection.
- Windows and Linux packages include editable launchers and use the connected
  node's block template instead of maintaining a second blockchain.

### Production-proof research

- Closed the raw Layout V5 composition interface. The prover now consumes an
  opaque verified execution capability and derives the setup, block challenge,
  final activation, output digest, and work digest internally.
- Added a provider-owned atomic path from verified ForgeMatrix execution through
  Layout V5 and the native BLAKE3 opening. Callers cannot substitute raw bridge
  fields or independently mix proof components.
- Production preflight requires the pinned n=33 geometry, the ordered 128
  structured claims, and the six statement-owned native BLAKE3 claims before
  expensive proving begins.
- Added bounded adversarial tests for block, setup, activation, output-digest,
  work-digest, claim-order, provenance, and scratch-cleanup failures.

## Compatibility and upgrade notes

- Devnet-14 keeps the current Devnet-0 chain, P2P protocol, wallet data format,
  and TCP port `18444`.
- Existing wallet data should be preserved. Replace the application binaries;
  do not delete the wallet data directory.
- Production proof tag 3 remains unavailable to consensus. Devnet blocks still
  use the small reference relation and its existing proof tag.
- Windows binaries are not code-signed and may show an unknown-publisher
  warning.

## Release acceptance

Do not publish the candidate until the exact release commit has passed:

- workspace formatting, warning-denied Clippy, MSRV checks, and the complete
  standard and feature-gated Rust test matrix;
- wallet typechecking, all frontend tests, and a production frontend build;
- Windows and Linux wallet and node builds;
- Windows and Linux CUDA/OpenCL standalone-miner packaging, backend inspection,
  and available-device differential smoke tests;
- binary version checks, archive extraction, launcher inspection, and a final
  independently verified SHA-256 manifest.

## Production status

Production activation remains fail-closed. The component and bounded
composition checks do not replace an unchanged full-size run. Mainnet still
requires the final model artifact and commitments, one exact n=33 end-to-end
proof with proof size, proving time, verification time, peak memory and disk
recorded, independent transcript and soundness review, adversarial public
testing, reproducible signed releases, and external security audit.
