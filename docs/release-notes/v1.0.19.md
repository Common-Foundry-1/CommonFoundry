# Common Foundry v1.0.19

This wallet update repairs catch-up after time offline. Updated relays can corroborate historical block IDs even after pruning their proof bodies, while archive peers still supply the full proofs. Agreement from two independent provider groups, proof validation, work rules and the newest-block checks remain required.

Historical peer reads no longer hold the shared node lock during disk I/O. Retained-history auditing uses smaller batches and reserves foreground service time, so checking old records does not monopolize live sync and status requests. The weights remain resident when configured; background auditing may finish later, and no audit checks are skipped.

Sync diagnostics distinguish the download target from locally available funds. A wallet behind a recently reported network height keeps catching up; a locally checked snapshot is no longer labeled caught up while downloads remain. The update also carries the deployed bounded fork-state cache and reserved validation capacity.

Existing wallets, keys and chain data are preserved. This release does not change the network identity, mainnet checkpoint, proof format or consensus rules. Mining uses the existing proof system.

Qualification and final package-signature evidence are recorded with the release artifacts.
