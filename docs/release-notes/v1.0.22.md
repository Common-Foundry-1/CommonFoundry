# Common Foundry v1.0.22 candidate

The pool no longer classifies every next-block transaction validation error as
missing payout funding. It preserves the signed payment and its reservation,
and retries transactions whose inputs remain present. Existing funding holds
can recover automatically when the unchanged transaction validates again, full
credit and fee coverage is restored, and no input conflict remains. Recovery
records a durable receipt.

The offline payout status report includes reserved outpoints. Validation logs
include the rejection, transaction ID, chain tip, next height and absent inputs.
Spent or conflicting inputs still block recovery. Legacy abandoned signatures
remain reserved for explicit review; no replacement-payment path is added.

This candidate combines the published v1.0.21 release corrections, the
pre-activation pool identity fix from PR #32, and payout recovery from PR #33.
The network, fork height 67,535 and proof rules are unchanged. Candidate build
and test receipts are separate from publication and live pool deployment.
